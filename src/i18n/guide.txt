## 1. 予実ナビでわかること

保守の{project}ごとに、**予算**（{contract}の総額を月数で均等に割った額）と**実績**（作業時間 × 時間単価）を比べ、選んだ期間の終わりにどこへ着地しそうかを見る画面です。

| 言葉 | 意味 |
|---|---|
| **予算** | {contract}の総額 ÷ {contract}の月数。月ごとに同じ額 |
| **実績** | 作業時間 × その月の時間単価（{member}の役職などで決まる） |
| **残予算** | 予算 − 実績。**残予算率** = 残予算 ÷ 予算 |
| **消化率** | 経過した月の実績の合計 ÷ 予算の合計。**{threshold} を超えると赤** |
| **着地見込み** | 選んだ期間の終わりまでの実績の見込み。予算を超えそうな{project}は**超過見込み**（赤）。案件詳細では{project}の終了時点の見込みも出ます |

赤は「消化率の超過」と「超過見込み」の 2 つだけです。赤が無ければ、いまのところ予算の範囲内です。

見るだけならどなたでも使えます。リソース計画・マスタ編集の変更は、編集の権限がある人が**保存**（マージリクエストの作成）し、**マージできるのはリーダー層だけ**です。マージされて初めて数値に反映されます（[7. リソース計画](#7)〜[9. 設定](#9)）。

## 2. 画面の移り方

| 場所 | 中身 |
|---|---|
| 上部のタブ | [全体](./) ・ [チーム](./teams) ・ [顧客](./customers) ・ [案件](./contracts) ・ [メンバー](./members) ・ [稼働実績](./workload) |
| 右上のボタン | [リソース計画](./plan) |
| 右端のアイコン | 歯車 [設定](./settings)（表示モード・テーマカラーもここ）、⋯ その他（[マスタ編集](./masters)（リーダー層向け）・この「使い方」・[データ確認](./data-check)・[計算ルール](./rules)）。⋯ の右上の数字はマージ待ちの件数 |

- 一覧の名前を押すと詳細（チーム詳細・顧客詳細・案件詳細・メンバー詳細）が開きます。ブラウザの「戻る」で一覧へ戻ると、絞り込み・並べ替え・スクロール位置はそのままです。
- スマートフォンでは、上の段にロゴと右上のボタン、下の段にタブが並びます。タブが入りきらないときは横にずらせます。
- 見出しの横の **?** にカーソルを合わせる（スマートフォンでは押す）と、その画面・欄の説明が出ます。

| 画面 | こんなときに |
|---|---|
| [全体](./) | 全体の予算・実績・残予算・消化率・着地見込みと、月ごとの推移を見る |
| [チーム](./teams) | 組織ごとに見る。上位の組織は配下の合計。チーム詳細では{project}別・{member}別の実績と組織の変遷 |
| [顧客](./customers) | {customer}ごとに見る。顧客詳細では{project}の一覧と担当チーム別 |
| [案件](./contracts) | {project}ごとに見る。赤い行（消化率の超過・超過見込み）から確認。案件詳細では月ごと・{member}別・作業ログ |
| [メンバー](./members) | 人ごとの計画と実績・稼働率。メンバー詳細では月ごと・{project}別・単価の変遷 |
| [稼働実績](./workload) | 運用保守と運用保守以外（提案・運用設計など）の稼働実績（人月）を、組織・{customer}・{member}別に。作業の種類ごとの内訳 |
| [データ確認](./data-check) | 実績に入らなかった作業や、単価の無い人などの警告（[10. データ確認](#10)） |

## 3. 表示条件（期間・チーム・着地見込み・単位）

画面上部の表示条件のバーで、どの画面も同じ条件に切り替わります。

- **期間**: 「今年度」「今月」「先月」「直近3か月」「直近12か月」「前年度」から選ぶか、開始月・終了月を指定します。カレンダーで日付を選んだときは、その日を含む月で集計します（データは月単位のため）。
- **チーム**: 選んだ組織とその配下をまとめて集計します。「全体」はすべての組織です。
- **着地見込み**: 期間の終わりまでの見込みの出し方を選びます（[5. 着地見込みの切り替え](#5)）。
- **単位**: 金額の表示を 百万円（既定・小数 1 桁）／千円／円 から選びます。明細の表、計算根拠、Excel 出力は単位に関係なく円です。

選んだ条件はページの URL に入ります。URL をそのまま共有すると、相手にも同じ表示が開きます。

## 4. 数値の読み方

- **計算基準日・確定済み**: 画面上部に、数値の基準になった日と、確定した月を出しています。作業時間はその月の翌月 {closingDay} 営業日に確定します。確定前の月は「速報」で、あとから少し変わることがあります（「速報を含む」の印）。
- **作業実績の取得**: 作業時間を最後に取り込んだ日時です。古いままのときは管理者に確認してください。
- **計算根拠**: 数値を押すと、その数値の式と実際に使った値（{contract}総額・単価・作業時間など）が開きます。「なぜこの金額なのか」を確かめるときに使います。
- **グラフ**: 右上の「拡大」で大きく表示します（スマートフォンでは全画面）。
- **Excel 出力**: 一覧の「Excel出力」で、いま表示している表をダウンロードします（金額は円）。
- **状態の印**: 一覧の「超過見込み」「消化率超過」「速報含む」で、注意が要る行がわかります。見出しを押すと並べ替えられます。

## 5. 着地見込みの切り替え

選んだ期間の終わりの着地は、まだ来ていない月の実績を次の 3 つの方法で見積もります。年度をまたぐ{project}は、案件詳細で終了時点の着地も確かめられます。表示条件の「着地見込み」で切り替えます（既定は {methodDefault}）。

| 方法 | 見積もり方 | 向いているとき |
|---|---|---|
| **{methodAssignment}** | リソース計画（誰を何人月充てるか）× 単価 | 体制の変更を見込みに入れたいとき |
| **{methodRecent3}** | 直近 {recentMonths} か月の実績の平均 × 残りの月数 | 最近の作業量がこの先も続きそうなとき |
| **{methodAll}** | {contract}開始から前月までの平均 × 残りの月数 | 月ごとの波が大きいとき |

{methodAssignment}は、リーダーがリソース計画を入れているほど正確になります。

## 6. よくある使い方

- **自分のチームの状況を見る**: 表示条件のチームで自分の組織を選ぶ → [全体](./) の数値と推移を見る。
- **危ない{project}を探す**: [案件](./contracts) で赤い行を確認 → 名前を押して案件詳細 → 月ごと・{member}別の実績で原因を見る。作業の種類ごとの内訳で、運用保守以外の作業が多くないかも確認できます。
- **人の割り当てを見直す**: [メンバー](./members) で計画と実績・稼働率を比べる → 必要なら [リソース計画](./plan) を直す。
  上の「運用保守以外を含む」にすると、提案・会社業務などの予定と実績も計画と実績の両方に入ります。
- **会議の資料にする**: 期間・チーム・単位を選んで URL を共有するか、Excel 出力を使います。

## 7. リソース計画（リーダー層向け）

[リソース計画](./plan) では、{member}一人ひとりを「どの{project}に、月何人月」充てるかを入れます。

1. 組織を選びます（配下の組織も含みます）。年度は「前の年度」「次の年度」で切り替えます。他の組織から自分の組織の{project}に入っている人は「応援」と表示されます。
2. 人ごとに 1 行です。行を開くと、{project}ごとの行と、運用保守以外の見込み（提案・設計・会社業務など）の種別ごとの行が出ます。
3. 月のセルの色は、その人のその月の合計（人月）を表します。

| セル | 意味 |
|---|---|
| 青 | 1.0 人月に満たない（空きがある） |
| 黄・「1.0 超」 | 1.0 人月を超えている（保存はできますが、見直してください） |
| 色なし | 0（計画なし）か、ちょうど 1.0 |

- **表の上のグラフ**は、表示中の人の月ごとの合計を運用保守と運用保守以外に分けて積み上げたものです。破線は人数 × 1.0 人月で、棒との差が組織の空きです。1.0 人月を超える人がいる月は「!2人」のように人数が出ます。
- **セルを押す**と、その月の人月をその場で直せます。「この月だけ」か「この月以降」を選んで「反映」します。0 か空にすると、その月の計画から外れます。
- **途中で人月が変わる**ときは、行の「＋ 変更」で「何月から何人月」を入れます。期間は画面が分けて保存します。「変更 n件」で、いつ何人月に変わったか・誰がいつ入れたかを確かめ・直せます。
- 人月でも時間でも入力できます（{standardHours} 時間 = 1 人月）。保存と表示は人月にそろえます。
- 保存のしかたはマスタ編集と同じです（[8. マスタ編集](#8)）。

## 8. マスタ編集（リーダー層向け）

[マスタ編集](./masters) では、{member}（所属・役職）・単価・組織の台帳と、目標を直します。

- **1 行 = 1 人・1 役職・1 組織**です。行を開くと、いつから何が変わったかの履歴が出ます。
- **異動・昇格・単価改定・組織変更**は、今の値を書き換えずに、行の「＋ 変更」で**変わる月と新しい値**を入れます。前の値はその前の月まで残るので、過去の数値は変わりません。
- 過去の月の数値が変わる操作をすると、確認の画面で「過去の計算結果が変わります（影響: n か月）」と、何が変わるかを出します。
- 「表で編集」と「CSV で編集」を切り替えられます。CSV では Excel からの貼り付けもできます（「反映」を押すまで表は変わりません）。
- **検証**: 保存の前に、データに問題がないかを画面が調べます。**赤はエラー**（直すまで保存できません）、**黄は警告**（保存はできます）。一覧の項目を押すと、その行へ移動します。
- **下書き**: 編集中の内容はこのブラウザに自動で保存されます。閉じてしまっても、次に開いたとき「下書きを復元する」で続きから編集できます。
- **保存**: 「GitLab に保存（マージリクエストを作成）」で、変更は新しいブランチに保存され、マージリクエストとしてマージ待ちになります（まだ数値には反映されません）。初めて保存する前に、[設定](./settings) でトークンを登録してください（[9. 設定](#9)）。
- **マージ**: **マージできるのはリーダー層（GitLab の Maintainer）だけ**です。リーダーは画面上部の「マージ待ちの変更」で「内容を見る」から変更を確かめ、「マージ」します。リーダー以外の人にはマージボタンが出ず、「マージはリーダーが行います」と出ます。不要な変更は作成者かリーダーが「取り下げ」ます。
- **目標**: 「目標」タブで、{team}・顧客・{project}ごとに「終了月までに残予算率 ◯% 以上」を入れます。上期・通期のように終了月の違う目標をいくつでも置けます。月ごとの目標は、開始月と終了月を同じ月にします。目標は各一覧の「目標」列と、詳細画面の「目標」に「達成見込み」「未達見込み」などで出ます。
- **反映**: マージのあと、画面が自動で作り直されます。数分たってからページを再読み込みすると、すべての画面の数値に反映されています。

## 9. 設定（表示・GitLab のトークン）

[設定](./settings) の一番上の「表示」で、表示モード（自動／ライト／ダーク）とテーマカラーを選べます。「自動」は、ライト／ダークを PC の設定に、テーマカラーを GitLab のテーマの色（GitLab に接続していなければブルー）に合わせます。

GitLab のトークンは、リソース計画・マスタ編集を保存する人だけが必要な設定です。見るだけの人は設定しなくてかまいません。

1. GitLab にログインし、「ユーザー設定 → アクセストークン」で、scope に **api** を付けた個人アクセストークンを作ります。
2. [設定](./settings) の「個人アクセストークン」に貼り付けて「登録」します。トークンは画面に再表示しません。
3. 「接続を確認」で、自分の権限と、マージできる立場（リーダー層）かどうかを確かめます。保存には Developer 以上、マージには Maintainer の権限が要ります。

- 既定では、ブラウザのタブを閉じるとトークンは消えます。「このブラウザに記憶する」をオンにすると残ります（共用の PC ではオンにしないでください）。

## 10. データ確認

[データ確認](./data-check) には、数値の精度に影響するデータの問題を出しています。

| 表示 | 意味 | 直し方 |
|---|---|---|
| 未紐付けの作業実績 | どの{project}にも結び付かず、実績に入っていない作業時間 | 作業実績の{customer}名・{project}名と{project}の対応を管理者に追加してもらう |
| 単価のないメンバー | 単価が無く 0 円で計算した作業 | マスタ編集の「単価」で、その役職（または人）の単価を追加する |
| メンバーマスタに無いメンバー | 作業実績にだけ出てくる人 | マスタ編集の「メンバー」で追加する |
| 除外した作業実績 | {customer}名が空の作業（社内会議など） | 対応は不要（集計の対象外） |

## 11. 困ったとき

| こんなとき | 確かめること |
|---|---|
| 数値が古い・変わらない | 画面上部の計算基準日と作業実績の取得日時。マージしたばかりなら数分後に再読み込み |
| {project}・人が見つからない | 表示条件の期間とチーム。期間外・別の組織だと出ません |
| 保存ボタンが押せない | 赤いエラーが残っていないか（[8. マスタ編集](#8)の検証）、トークンを登録したか（[9. 設定](#9)） |
| 「他の人が先に更新しました」と出た | 編集内容は下書きに残っています。数分たってから再読み込みし、「下書きを復元する」で最新のデータに当て直します |
| 「権限がありません」と出た | 設定の「接続を確認」で権限を確認し、管理者に相談する |
| マージボタンが出ない | マージはリーダーが行います。リーダーに依頼してください |
| 数値の出し方が知りたい | 数値を押して計算根拠を見るか、[計算ルール](./rules) を見る |
