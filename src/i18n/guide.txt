## 1. 予実ナビでわかること

{project}ごとに、**予算**（{contract}の総額を月数で均等に割った額）と**実績**（作業時間 × 時間単価）を比べ、選んだ期間の終わりにどこへ着地しそうかを見る画面です。

| 言葉 | 意味 |
|---|---|
| **予算** | {contract}の総額 ÷ {contract}の月数。月ごとに同じ額 |
| **実績** | 作業時間 × その月の時間単価（{member}の役職などで決まる） |
| **残予算** | 予算 − 実績。**残予算率** = 残予算 ÷ 予算 |
| **消化率** | 経過した月の実績の合計 ÷ 予算の合計。**{threshold} を超えると赤** |
| **着地見込み** | 選んだ期間の終わりまでの実績の見込み。予算を超えそうな{project}は**超過見込み**（赤）。案件詳細では{project}の終了時点の見込みも出ます |

赤は「消化率の超過」と「超過見込み」の 2 つだけです。チームや顧客など{project}をまとめた単位は、合計の着地がマイナスのときだけ赤になります。赤が無ければ、いまのところ予算の範囲内です。

見るだけならどなたでも使えます。リソース計画・マスタ編集の変更は、編集の権限がある人が**保存**（マージリクエストの作成）し、**マージできるのはリーダー層だけ**です。マージされて初めて数値に反映されます（[7. リソース計画](#7)〜[9. 設定](#9)）。

## 3. 表示条件（期間・チーム・着地見込み・単位）

画面上部の表示条件のバーで、どの画面も同じ条件に切り替わります。

- **期間**: 「今年度」「今月」「先月」「今後3か月」「直近12か月」「前年度」から選ぶか、開始月・終了月を指定します。カレンダーで日付を選んだときは、その日を含む月で集計します（データは月単位のため）。
- **チーム**: 選んだ組織とその配下をまとめて集計します。「全体」はすべての組織です。
- **着地見込み**: 期間の終わりまでの見込みの出し方を選びます（[5. 着地見込みの切り替え](#5)）。
- **単位**: 金額の表示を 百万円（既定・小数 1 桁）／千円／円 から選びます。明細の表、計算根拠、Excel 出力は単位に関係なく円です。

選んだ条件はページの URL に入ります。URL をそのまま共有すると、相手にも同じ表示が開きます。

## 4. 数値の読み方

- **今日・確定済み**: 画面上部に、数値の基準になる今日（日本時間）と、確定した月を出しています。作業実績がいつの時点のものかは「作業実績の取得」の日時で分かります（取り込みが止まった日も今日は進みます）。作業時間はその月の翌月 {closingDay} 営業日に確定します。確定前の月は「速報」で、あとから少し変わることがあります（「速報を含む」の印）。
- **作業実績の取得**: 作業時間を最後に取り込んだ日時です。古いままのときは管理者に確認してください。
- **計算根拠**: 数値を押すと、その数値の式と実際に使った値（{contract}総額・単価・作業時間など）が開きます。「なぜこの金額なのか」を確かめるときに使います。
- **グラフ**: 右上の「拡大」で大きく表示します（スマートフォンでは全画面）。
- **Excel 出力**: 一覧の「Excel出力」で、いま表示している表をダウンロードします（金額は円）。
- **状態の印**: 一覧の「超過見込み」「消化率超過」「速報含む」で、注意が要る行がわかります。見出しを押すと並べ替え、見出しの右端の漏斗ボタンで列ごとに絞り込めます（文字は値の一覧と検索、数値は以上〜以下、日付・年月は以降〜以前。年・年月・日のどれでも入れられ、年のボタンでその年だけ）。表の上の「列」で、出す列と並び順を変えられます。最初は出していない列（時間・人月・顧客・所属など）もここで選べます（先頭の列は固定。このブラウザに覚えます。「元に戻す」で既定）。

## 5. 着地見込みの切り替え

選んだ期間の終わりの着地は、まだ来ていない月の実績を次の 3 つの方法で見積もります。年度をまたぐ{project}は、案件詳細で終了時点の着地も確かめられます。表示条件の「着地見込み」で切り替えます（既定は {methodDefault}）。

| 方法 | 見積もり方 | 向いているとき |
|---|---|---|
| **{methodAssignment}** | リソース計画（誰を何人月充てるか）× 単価 | 体制の変更を見込みに入れたいとき |
| **{methodRecent3}** | 直近 {recentMonths} か月の実績の平均 × 残りの月数 | 最近の作業量がこの先も続きそうなとき |
| **{methodAll}** | {contract}開始から前月までの平均 × 残りの月数 | 月ごとの波が大きいとき |

{methodAssignment}は、リーダーがリソース計画を入れているほど正確になります。

## 6. よくある使い方

- **自分のチームの状況を見る**: 表示条件のチームで自分の組織を選ぶ → [全体](./) の数値と推移を見る。
- **危ない{project}を探す**: [案件](./contracts) で赤い行を確認 → 名前を押して案件詳細 → 月ごと・{member}別の実績で原因を見る（他{team}の人には「応援」、他部署の人には「ヘルプ」が付きます）。作業の種類ごとの内訳で、運用保守以外の作業が多くないかも確認できます。
- **人の割り当てを見直す**: [メンバー](./members) の「計画とのずれ」でアサイン漏れや古い計画を探す → 必要なら [リソース計画](./plan) を直す。
  上の「運用保守以外を含む」にすると、提案・会社業務などの予定と実績も計画と実績の両方に入ります。
- **今月を月の途中で抑える**: 期間に今月を含めると、全体・チーム・顧客・案件の詳細に「今月の進捗」が出ます。作業時間の速報を毎日足した累計を、今月の予算（目標があれば目標の残予算率を除いた額）を営業日で割った目安と比べ、「残り何営業日の予算がいくらか」と「このペースの月末」を出します。目安を超えていたら、残りの稼働を抑える目安にします。
- **会議の資料にする**: 期間・チーム・単位を選んで URL を共有するか、Excel 出力を使います。

## 7. リソース計画（リーダー層向け）

[リソース計画](./plan) では、{member}一人ひとりを「どの{project}に、月何人月」充てるかを入れます。

1. 組織を選びます（配下の組織も含みます）。表示する月は開始月〜終了月で選びます（既定は今月から 12 か月、最大 24 か月。◀ ▶ で 1 か月ずつずらせます）。他の組織から自分の組織の{project}に入っている人は「応援」と表示されます。
2. 人ごとに 1 行です。名前（▸）を押すと開き、{project}ごとの行と、運用保守以外の見込み（提案・設計・会社業務など）の種別ごとの行が出ます。まだ行の無い{project}や種別（「その他」など）は、人の行の「＋ 作業」で選んで入れます（候補は種別が先、その後に{project}）。表の上の「すべて開く」で表示中の人をまとめて開閉でき、開いた状態はタブを閉じるまで残ります。
3. 月のセルの色は、その人のその月の合計（人月）を表します。

| セル | 意味 |
|---|---|
| 青 | 1.0 人月に満たない（空きがある） |
| 黄・「1.0 超」 | 1.0 人月を超えている（保存はできますが、見直してください） |
| 赤紫・「なし」 | 今月以降に計画が何も入っていない人の月（名前の横に「計画なし」） |
| 色なし | 0（計画なし）か、ちょうど 1.0 |

- **見出しを押すと並べ替え**、見出しの漏斗で列ごとに絞り込めます。月・期間計の列は人月の範囲（1.01 以上で 1.0 超の人、0.99 以下で空きのある人）、メンバーの列は名前で選びます。グラフと合計行は絞り込んだ人だけの値になります。
- **表の上のグラフ**は、表示中の人の月ごとの合計を運用保守と運用保守以外に分けて積み上げたものです。破線は人数 × 1.0 人月で、棒との差が組織の空きです。1.0 人月を超える人がいる月は「!2人」のように人数が出ます。
- **セルを押す**と、その月の人月をその場で直せます。「この月だけ」か「この月以降」を選んで「反映」します。0 か空にすると、その月の計画から外れます。{project}を足すとき、その期間に契約が無い{project}は「契約期間外」と出て後ろに並びます。
- **途中で人月が変わる**ときは、行の「＋ 変更」で「何月から何人月」を入れます。期間は画面が分けて保存します。「変更 n件」で、いつ何人月に変わったか・誰がいつ入れたかを確かめ・直せます。
- 人月でも時間でも入力できます（{standardHours} 時間 = 1 人月）。保存と表示は人月にそろえます。
- **目標を下回りそうなとき**は、表の上に「▲ 未達見込み」の目標が出ます（今の計画、編集中は編集後の計画で判定）。月の見出しの赤い「!」は、その月の計画が目標の上限（予算 ×（1 − 目標の残予算率））を超える月です。保存は止めません。
- **計画が何も入っていない人**（表示中の今月以降に、{project}も運用保守以外も 0）は、名前の横に「計画なし」が付き、月は赤紫の「なし」になります。表の上の「計画なし n人」を押すとその人だけを表示します。不在の人、応援の人、所属の無い人（他部署のヘルプ）、下に組織がある組織の直属の人（部長など）、その組織に所属していない月は対象外です。
- **保存の前に「変更の影響」**で、{project}ごとの着地の増減と残予算（表示条件の期間・{project}終了時点）、残予算率が変わる目標を前 → 後で確かめられます。実績で確定した月だけの変更なら「着地見込みは変わりません」と出ます。
- 保存のしかたはマスタ編集と同じです（[8. マスタ編集](#8)）。

## 8. マスタ編集（リーダー層向け）

[マスタ編集](./masters) では、{member}（所属・役職）・単価・組織の台帳と、{project}の期間・金額、目標、祝日を直します。

- **1 行 = 1 人・1 役職・1 組織**です。行を開くと、いつから何が変わったかの履歴が出ます。
- **異動・昇格・単価改定・組織変更**は、今の値を書き換えずに、行の「＋ 変更」で**変わる月と新しい値**を入れます。前の値はその前の月まで残るので、過去の数値は変わりません。
- 過去の月の数値が変わる操作をすると、確認の画面で「過去の計算結果が変わります（影響: n か月）」と、何が変わるかを出します。
- 「表で編集」と「CSV で編集」を切り替えられます。CSV では Excel からの貼り付けもできます（「反映」を押すまで表は変わりません）。{member}と{project}は表だけで編集します。
- **{member}**: 社員番号・氏名は人事データから取り込むため、登録済みの人では変えられません。所属・役職などは直せます。
- **検証**: 保存の前に、データに問題がないかを画面が調べます。**赤はエラー**（直すまで保存できません）、**黄は確認要求**（保存はできます。確かめて判断します）。一覧の項目を押すと、その行へ移動します。
- **下書き**: 編集中の内容はこのブラウザに自動で保存されます。閉じてしまっても、次に開いたとき「下書きを復元する」で続きから編集できます。
- **保存**: 「GitLab に保存（マージリクエストを作成）」で、変更は新しいブランチに保存され、マージリクエストとしてマージ待ちになります（まだ数値には反映されません）。初めて保存する前に、[設定](./settings) でトークンを登録してください（[9. 設定](#9)）。
- **マージ**: **マージできるのはリーダー層（GitLab の Maintainer）だけ**です。リーダーは画面上部の「マージ待ちの変更」で「内容を見る」から変更を確かめ、「マージ」します。リーダー以外の人にはマージボタンが出ず、「マージはリーダーが行います」と出ます。不要な変更は作成者かリーダーが「取り下げ」ます。
- **{project}**: 「{project}」タブに保守{project}の一覧（顧客・{project}名・開始月・終了月・金額・担当{team}）が出ます。登録済みの{project}で直せるのは期間・金額・担当{team}だけです（顧客名・{project}名などは他システムから取り込みます）。取り込みに無い{project}は「＋ 新しい{project}」で登録します（データ確認の「{project}に登録」から来ると、正式な{project}ID・顧客名・{project}名が入った状態で開きます）。金額・期間を変えると期間の月の予算が変わるので、過去の月にかかるときは確認が出ます。
- **顧客**: 「顧客」タブで顧客ごとの既定の担当{team}を入れると、担当{team}が空の{project}はその{team}として集計します。例外の{project}だけ「{project}」タブで担当{team}を書きます。
- **未設定・仮の値**: 表の上の「担当{team}未設定」「金額未入力」「仮の単価」を押すと、その行だけになります。動作確認用の単価は「仮の値」を「仮」にしておくと、本番の値と区別できます。
- **祝日**: 「祝日」タブで国民の祝日と会社の休日（年末年始など）を足します。営業日の数え方（工数の確定日・今月の進捗の目安）に使います。
- **目標**: 「目標」タブで、{team}・顧客・{project}ごとに「終了月までに残予算率 ◯% 以上」を入れます。上期・通期のように終了月の違う目標をいくつでも置けます。月ごとの目標は、開始月と終了月を同じ月にします。目標は各一覧の「目標」列と、詳細画面の「目標」に「達成見込み」「未達見込み」などで出ます。
- **反映**: マージのあと、画面が自動で作り直されます。数分たってからページを再読み込みすると、すべての画面の数値に反映されています。

## 9. 設定（表示・GitLab のトークン）

[設定](./settings) の一番上の「表示」で、表示モード（自動／ライト／ダーク）とテーマカラーを選べます。「自動」は、ライト／ダークを PC の設定に、テーマカラーを GitLab のテーマの色（GitLab に接続していなければブルー）に合わせます。文字が読みにくいときは「文字の大きさ」を小・標準・やや大・大・特大から選べます（このブラウザに保存）。

GitLab のトークンは、リソース計画・マスタ編集を保存する人だけが必要な設定です。見るだけの人は設定しなくてかまいません。

1. [設定](./settings) の「トークンを作成 ↗」を押すと、GitLab の個人アクセストークンの作成画面が新しいタブで開きます（名前と scope **api** は入力済み）。有効期限を選んで作成し、表示された値をコピーします。
2. [設定](./settings) の「個人アクセストークン」に貼り付けて「登録」します。トークンは画面に再表示しません。
3. 「接続を確認」で、自分の権限と、マージできる立場（リーダー層）かどうかを確かめます。保存には Developer 以上、マージには Maintainer の権限が要ります。

- 既定では、ブラウザのタブを閉じるとトークンは消えます。「このブラウザに記憶する」をオンにすると残ります（共用の PC ではオンにしないでください）。

一番下の「バージョン情報」に、このアプリのバージョン・コミット・ビルド日時が出ます。問い合わせのときに伝えてください。

## 10. データ確認

[データ確認](./data-check) には、数値の精度に影響するデータの問題を出しています。**エラー**は公開を止めるもの、**確認要求**は公開を止めず人が確かめて判断するものです。データを自動で直したり登録したりはしません。「{project}に登録」「{project}を開く」「マスタで直す」で、マスタ編集の直す場所が開きます。

作業実績の一覧（未紐付け・キーワードに合致しない作業・未登録の作業コード）には「作業した人」の列があります。押すと人ごとの時間、列の漏斗で人を選んで絞り込めます。表の上の「人ごと」に切り替えると、人ごとにまとめ直します（誰に確かめればよいかが分かります）。

| 表示 | 意味 | 直し方 |
|---|---|---|
| 未紐付けの作業実績 | どの{project}にも結び付かず、実績に入っていない作業時間。理由が「未登録の案件」のものは、作業名から抜き出した{project}名が{project}の一覧に無いもの | 作業実績の{customer}名・{project}名と{project}の対応を管理者に追加してもらう。「未登録の案件」は{project}の追加か、表記の違いなら別名の登録を管理者に頼む |
| 契約期間外の実績 | {project}の名前は合うのに、どの契約の期間にも入らない作業（実績に入っていない）。契約期間・実績の期間・作業した人を並べ、時間を押すと月ごと | 契約が続いているなら「{project}を開く」で期間を延ばすか更新の契約を足す。作業実績の入力の誤りなら作業実績を直す |
| キーワードに合致しない作業 | 作業名のキーワードで運用保守を抜き出す{project}で、キーワードに合わず運用保守以外として数えた作業（実績に入っていない） | 運用保守の作業が混ざっていたら、キーワードの追加を管理者に頼む |
| 未登録の作業コード | 作業名が運用保守のキーワードに合うのに、{project}との対応表に無い（または対応の期間外の）作業コード（作業名の{project}名で結び付いたものは除く） | {project}を確かめて、作業コードの対応を管理者に追加してもらう |
| 作業名が変わった作業コード | 同じ作業コードで作業名が変わったもの。キーワードに合わなくなった・合うようになったものも分かる | 運用保守かどうかを確かめる |
| 正式な案件IDの無い{project} | 案件管理システムの正式な案件と照合していない{project}（{customer}名・{project}名は手入力のまま）。候補は{project}名が同じもの | 正式な案件IDを管理者に入れてもらう |
| マスタに無い正式な案件 | 案件管理システムにあって、{project}のマスタに無い案件 | 保守の{project}なら「{project}に登録」で登録する（「同じ案件名の{project}」があれば二重登録でないか確かめる） |
| 未設定・仮の値 | 担当{team}未設定・金額未入力・単価未設定の{project}や役職と、動作確認用の仮の単価 | 「マスタで直す」で値を入れる。仮の単価は本番の値にしたら「仮の値」を外す |
| 単価のないメンバー | 単価が無く 0 円で計算した作業（人ごとに 1 行。時間を押すと月ごと） | マスタ編集の「単価」で、その役職（または人）の単価を追加する |
| メンバーマスタに無いメンバー | 作業実績にだけ出てくる人。時間は集計に含め、{project}の実績は個人単価が無ければ 0 円。上の数字の「マスタに無いメンバー」に人数が出ます | マスタ編集の「メンバー」で追加する（他部署の人は所属チームを空にするとヘルプとして本人の役職の単価で計算） |
| 除外した作業実績 | {customer}名が空の作業（社内会議など） | 対応は不要（集計の対象外） |

## 11. 困ったとき

| こんなとき | 確かめること |
|---|---|
| 数値が古い・変わらない | 画面上部の作業実績の取得日時（今日より前なら取り込みが止まっている）。マージしたばかりなら数分後に再読み込み |
| {project}・人が見つからない | 表示条件の期間とチーム。期間外・別の組織だと出ません |
| 保存ボタンが押せない | 赤いエラーが残っていないか（[8. マスタ編集](#8)の検証）、トークンを登録したか（[9. 設定](#9)） |
| 「他の人が先に更新しました」と出た | 編集内容は下書きに残っています。数分たってから再読み込みし、「下書きを復元する」で最新のデータに当て直します |
| 「権限がありません」と出た | 設定の「接続を確認」で権限を確認し、管理者に相談する |
| マージボタンが出ない | マージはリーダーが行います。リーダーに依頼してください |
| 数値の出し方が知りたい | 数値を押して計算根拠を見るか、[計算ルール](./rules) を見る |
