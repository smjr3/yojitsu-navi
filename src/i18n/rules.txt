## 1. 用語

| 用語 | 意味 |
|---|---|
| **{project}** | 予実を管理する単位。1 {project} = 1 {contract}。{contract}の更新・金額変更は、同じ{project}の別の{contract}の行（別 ID）として持ちます |
| **予算** | {contract}の総額を{contract}月数で均等割りした、月ごとの予算額 |
| **実績** | 作業時間 × その月に有効な時間単価（{costTypes}） |
| **残予算** | 予算 − 実績。**残予算率** = 残予算 ÷ 予算 |
| **消化率** | 経過月の累計実績 ÷ 経過月の累計予算。**{threshold} を超えると赤** |
| **着地見込み** | 選んだ期間の終わり時点の実績と残予算の予測。{project}ごとに超過／範囲内を判定 |
| **年度** | {fyStartMonth}月始まり。FY{fy} = {fy}年{fyStartMonth}月〜{fyEndYear}年{fyEndMonth}月。年度番号は開始年 |
| **計算基準日** | 現在 **{asOf}**（基準月 {asOfMonth}）。ビルド時の日付（環境変数 `YOJITSU_AS_OF` で固定可） |

## 2. 月の扱い

- 年月は `YYYY-MM`。{contract}の月数は開始月と終了月の**両方を含む**数です（{fyFirstMonth}〜{fyLastMonth} は 12 か月）。
- 月の途中で始まる・終わる{project}も均等割りにします（日割りしません）。
- 開始月 > 終了月、または総額が負・数値でない{project}は計算から除外し、「データ確認」に警告を出します。0 円の{project}は有効（予算 0）です。
- {contract}ID が重複した場合は最初の行だけを使います。

## 3. 月次予算（契約額の月割り）

```
基本額   = floor(契約総額 ÷ 契約月数)
端数     = 契約総額 − 基本額 × 契約月数
月の予算 = 基本額（最終月だけ 基本額 + 端数）
```

全月の合計は必ず契約総額に一致します。例: 38,000,000 円 ÷ 12 か月 → 3,166,666 円 × 11 か月 + 3,166,674 円（最終月）。

## 4. 作業実績の紐付け（{customer}名・{project}名のマッピング）

作業実績の{customer}名・{project}名は、照合の前に**正規化**します。

1. Unicode NFKC（全角英数・半角カナを統一）
2. 前後の空白を除去し、連続する空白（全角含む）を 1 つの半角空白に
3. 小文字化
4. 法人格（株式会社・(株)・㈱・有限会社・合同会社・Inc.・Co., Ltd.・Ltd.・Corp.・LLC）を前後から除去

照合の手順:

1. {customer}名が空の作業実績は**除外**します（「データ確認」に合計時間を表示）。
2. `({customer}, {project})` の完全一致ルールを探し、無ければ `({customer}, 空)` のルール（その{customer}の全工数）を探します。
3. ルールが指す{contract}のうち、**作業日の月が{contract}期間に入るもの**を選びます。更新{contract}（同じ名前で別 ID）は作業日で自動的に振り分けられます。
4. 該当が 2 件以上なら ID 昇順で最初を採用し、警告を出します。該当が無ければ「期間外」として未紐付けになります。
5. ルール自体が無い作業実績は「ルールなし」として未紐付けになります。

未紐付けの作業実績は実績に含まれません。「データ確認」で `({customer}名, {project}名)` ごとの時間と件数を確認できます。

**作業名のキーワード**: 1 つの{project}に運用保守と導入・設計などが混ざるときは、ルールに作業名のキーワード（`task_include` = 含む、`task_exclude` = 除く。`|` 区切りで複数）を指定できます。

- 作業名がキーワードのどれかを含めば、その{project}の**運用保守**として数えます。除くキーワードを含む作業は、含むに合っても対象外です。全角半角・大文字小文字・空白は区別しません。
- 合致しない作業は**運用保守以外**として数えます（{project}の実績には入りません）。種別は作業種別の分類表で決め、分類表に無ければ「その他」です。「データ確認」の「キーワードに合致しない作業」で作業名ごとに確認できます。
- 同じ{customer}名・{project}名で{contract}が複数あるときも、キーワードで振り分けられます。

## 5. 履歴マスタ（{team}・{member}・単価）

{team}・{member}・単価は「適用開始月（effective_from）」付きの履歴です。**月 m に有効なレコード = 同じキーで適用開始月 ≤ m のうち最も新しいもの**。昇格・異動・単価改定は行を追加して表現し、過去月は当時の値で計算されます。

退職・休職・産休・育休・契約終了も行を追加して表し（在籍の列）、その行の月から在籍しない扱いです。ただし**その月に計画か実績があれば、その月までは稼働**とみなします（リソース計画の人数 × 1.0 に数え、警告も出しません）。実績は離脱後の分も捨てずに数えます。

## 6. 時間単価の決め方

月 m の{member} x の単価は次の順で決まります。

1. 単価表に **社員番号** のレコードがあればそれ（パートナー個人単価）
2. 無ければ、その月の{member}マスタの**役職**で単価表を引く
3. どちらも無ければ **単価 0 円**として計算し、「単価なし」警告を出す（{member}×月ごと）
4. {member}マスタに存在しない ID は 1 だけ試し、無ければ 0 円。「不明{member}」警告を出す

## 7. 月次の実績

```
メンバーごとの実績 = round(その月の作業時間の合計 × 単価)   ← 円に四捨五入
月の実績            = Σ メンバーごとの実績
```

実績行には当時の所属{team}を持たせるので、他{team}からの応援も「どの{team}の人がどれだけ作業したか」で追えます。日付が不正な作業実績、時間が 0 以下の作業実績は無視します。

## 8. 月の状態（確定・速報・未来）

| 状態 | 条件 |
|---|---|
| **未来（予定）** | 基準月より後の月 |
| **速報** | 基準月、または 基準月より前で **確定日** を迎えていない月 |
| **確定** | 確定日を過ぎた月 |

**確定日 = 翌月の第 {closingDay} 営業日**（営業日 = 土日でも祝日・会社休日でもない日）。現在の確定済み最新月は **{lastFinalMonth}** です。速報月を含む集計には「速報を含む」バッジが付きます。

## 9. 営業日と人月換算

- 営業日数 = その月の暦日から土日と祝日（holidays.csv）を除いた日数
- 人月（標準）= 作業時間 ÷ **{standardHours}h**
- 人月（カレンダー）= 作業時間 ÷ (営業日数 × **{dayHours}h**)。複数月は月ごとに計算して合算

## 10. 着地見込み（{project}ごと・選んだ期間の終わりまで）

```
期間内の契約月 = 選んだ期間の月 ∩ 契約期間
実績月         = 期間内の契約月のうち 基準月より前の月（速報を含む）
残り月         = 期間内の契約月のうち 基準月以降の月（基準月を含む）
期間の予算     = Σ 期間内の契約月の予算
実績       = Σ 実績月の実績
着地実績       = 実績 + 残り見込み
着地差       = 期間の予算 − 着地実績   （マイナスなら「超過見込み」）
```

残り見込みの出し方（画面の「着地見込みの方式」で切替。既定は **{methodDefault}**）:

| 方式 | 残り見込み |
|---|---|
| **{methodAssignment}** | Σ（残り月 × リソース計画: 配分人月 × {standardHours}h × その月の単価）。リソース計画が無ければ 0 |
| **{methodRecent3}** | {contract}期間内で基準月より前の **直近 {recentMonths} か月** の実績の平均 × 残り月数（年度をまたいでよい。実績が {recentMonths} か月未満ならある分で平均、0 か月なら 0） |
| **{methodAll}** | {contract}開始月から基準月の前月までの全月の実績の平均 × 残り月数 |

期間に 1 か月も掛からない{project}は対象外（期間の予算 0・判定なし）です。案件詳細では、期間に加えて{contract}期間の全月を対象にした**{project}終了時点の着地**も出します（式は同じ）。

## 11. 画面での集計

- 期間は両端を含みます。{team}を選ぶと、その{team}と**配下すべての{team}**の{project}を合算します。
- 主担当{team}が空・未知の{project}は「未設定」グループに入ります。
- {team}一覧は**期間の終了月時点の組織**で表示します（組織変更があった場合、過去の期間は当時の階層になります）。
- 消化率の「経過月」は期間内で基準月以前の月です。期間が未来だけなら消化率は計算できません（—）。
- 前年同期比は、経過月と同じ月を 1 年前にずらして比べます。1 年前の実績が無いときは「比較データなし」と表示します。

## 12. 金額と表示

- 金額は内部では常に円の整数。表示は **百万円（既定）/ 千円 / 円** を切替できます（百万円 = 円 ÷ 100万 を小数1桁に四捨五入、千円 = 円 ÷ 1000 を四捨五入）。計算根拠の値と Excel 出力は常に円です。
- 割合は小数 1 桁（例 103.4%）。時間は `147.75h`、日付は `{asOf}`、月は `{asOfMonth}`（URL と Excel では `{asOfYm}`）。
- **赤い表示は「消化率 > {threshold}」と「着地が超過」の 2 つだけ**です。黄色の警告はありません。赤は色だけでなく ▲ の印と文字でも示します。

## 13. 計算根拠

画面のすべての数値はクリックすると「式 ＋ 実際に使った値」が開きます。実績は {member}ごとの実績行から元の作業ログ（誰が・いつ・何を・何時間）まで辿れます。

## 14. データ検証

CI では次の問題があると公開を止めます: {contract}ID の重複・期間の逆転・金額の不正、存在しない{project}への紐付け、アサインの未知 ID・配分の範囲外（1 人の月合計 > 1.0）、{team}の未知の親・循環、{member}の未知の{team}・区分の不正、単価の不正、日付・年月の形式不正。未紐付け工数や単価なしは警告として「データ確認」に表示し、公開は止めません。

## 15. {member}別（人ごとの予実）

{member}ごとに、**計画（予）** と **実績（実）** を比べます。基準時間（1 人月）は現在 **{standardHours}h** です。

```
計画時間 = 配分人月 × 基準時間                       （案件・月ごと。同じ案件・月のアサインは配分を合計）
計画額 = round(計画時間 × その月の時間単価)         （案件・月ごとに円に丸めて合計）
実績 = その人の実績行（作業時間 × その月の時間単価）（案件詳細の実績と同じ値）
差額     = 計画額 − 実績                       （プラス = 計画より実績が少ない）
稼働率   = 実績時間 ÷ 計画時間                       （計画時間 0 なら —）
```

- 時間単価は「6. 時間単価の決め方」と同じ（個人単価 → その月の役職の単価）。単価改定・昇格の月から新しい単価になります。
- アサインは{contract}期間内の月だけ数えます（期間外の月・除外された{project}への配分は計画 0）。
- アサインの無い{project}・月への作業（応援など）は「アサイン外」の時間として実績に含め、別に表示します。
- **比べるのは経過月（期間内で基準月 {asOfMonth} 以前の月）だけ**です。未来の月は実績が無いため、期間全体の計画と比べると稼働率・差額がよく見えてしまうからです。期間全体の計画は注記と月次推移に出します。
- 所属{team}・役職は各月の当時の値で計算し、一覧では期間の終了月（未来なら基準月）の値で表示・絞り込みします。
- メンバーマスタに無い ID でも作業実績があれば表示します（名前は作業ログの表記、個人単価が無ければ 0 円）。
- 稼働率が 100% を超えても、差額がマイナスでも**赤にはしません**（赤は消化率超過と超過見込みだけ。チーム・顧客などまとめた単位の超過見込みは、合計の着地がマイナスのときだけ赤）。
- **計画とのずれ**は確定した月だけで、メンバー × {project}ごとに比べます。計画なし（アサインが無いのに作業あり）・実績なし（アサインがあるのに作業なし）・多い／少ない（実績が計画から 30% 以上ずれている）。差が 16h（0.1 人月）未満は出しません。

## 16. 目標（{team}・顧客・{project}）

マスタ編集の「目標」で、{team}・顧客・{project}ごとに「終了月までに残予算率 ◯% 以上」を目指す目標を置けます。

- 期間は「開始月（空なら終了月を含む年度の最初の月）〜終了月」です。表示条件の期間には左右されません。
- 残予算率 = (予算 − 着地) ÷ 予算。着地 = 基準月より前の月の実績 ＋ 終了月までの見込み（[10](#10) と同じ式。方式は表示条件の「着地見込み」）。
- 終了月が基準月より前なら実績で確定し「達成／未達」、それ以外は見込みで「達成見込み／未達見込み」です。残予算率が目標以上なら達成です。目標はマイナスでも置けます（超過している対象を -100% から -50% に減らす、など）。このとき今月の上限・目標の上限は予算を超えます。
- {team}は基準月の組織で、配下の{team}の{project}を含みます。顧客は顧客名（表記ゆれは [4](#4) と同じ正規化）でまとめます。
- 目標は予算・実績・着地見込みの計算には使いません。月次推移のグラフでは、目標がある月に「目標の上限」（その月の予算 ×（1 − 目標の残予算率））を赤の破線で重ねます。上期・通期の目標でも各月に同じ率を掛けた目安です。今月の進捗の「今月の上限」にも使います（§18）。

## 17. 作業種別と運用保守以外の工数

作業実績の「作業種別」を、分類表（`task-types.csv`）で **運用保守** と **運用保守以外（提案・運用設計など）** に分けます。

- **運用保守以外の作業は{project}の実績に入れません**（実績・消化率・着地見込みのどれにも入りません）。保守契約の予算の外の仕事だからです。
- 運用保守以外は、顧客名の無い作業（会社業務など）も数えます。顧客名の無い運用保守の作業は従来どおり除外します。
- {member}別・{member}詳細で「運用保守以外を含む」にすると、**計画と実績の両方に**運用保守以外を足します。計画 = 運用保守以外の予定の人月 × {standardHours}h × 単価、実績 = 運用保守以外の作業時間 × 単価。作業種別は分類表の `group`（種別）で束ね、同じ種別の予定と比べます。全体・{team}・顧客・{project}の画面には足しません（運用保守以外には予算が無いためです）。
- 稼働実績画面と「作業種別の内訳」では運用保守以外の金額を出さず、時間と人月（時間 ÷ {standardHours}h）だけを「稼働実績」画面と各詳細の「作業種別の内訳」に出します。1 人の稼働の上限を考えるときに、保守と合わせて見るためです。
- 分類表の `match` を「含む」にした行は、作業名にその作業種別を含めば該当します（作業名に識別子や補足が付いていても同じ作業種別にまとまります）。完全一致の行が先で、無ければファイルの順に最初に含む行です。
- {project}のルールに作業名のキーワード（§4）があれば、運用保守かどうかはキーワードで決めます（分類表より優先）。
- 分類表に無い作業種別は **運用保守として数え**、「データ確認」に警告を出します。分類表に登録すれば消えます。分類表が無いときは、すべて運用保守です。
- 「作業種別の内訳」の実績は、{member}ごとの実績を作業種別の時間で按分した額です（1 円単位で合計が{project}の実績と一致します）。
- 稼働実績画面の{team}は {member}の所属（期間の終了月、未来なら基準月）で数えます。応援先の{project}の作業も、その人の所属{team}に入ります。

## 18. 今月の進捗（日別の速報）

全体・{team}・顧客・{project}の詳細で、選んだ期間に今月（計算基準日の月）が入っているときに出します。月の確定を待たず、毎日取り込む作業時間（速報）で今月の進捗を見るためのものです。

- **今月の上限** = 今月の予算（対象の{project}の月次予算の合計）。{team}・顧客・{project}に今月を含む目標があれば、今月の予算 ×（1 − 目標の残予算率）です。目標が複数あるときは期間の短いもの（月ごとの目標を年度の目標より優先）を使います。
- **目安** = 今月の上限 × 経過した営業日 ÷ 今月の営業日。土日・祝日は増えません。
- **今日までの実績** = 今月の作業時間 × 単価の、作業実績のある最後の日までの累計（速報。運用保守以外は入りません）。
- **残り n 営業日の予算** = 今月の上限 − 今日までの実績。1 日あたりはこれを残りの営業日で割った額です。
- **このペースの月末** = 今日までの実績 + これまでの営業日 1 日あたりの平均 × 残りの営業日。上限を超えると赤の印を出します。
- 経過した営業日は、作業実績のある最後の日（データ全体）までで数えます。日ごとの額は {member}ごとに丸める前の値なので、月の実績と数円ずれることがあります。
- {team}詳細の「メンバーごとの今月の時間」: {team}の{project}の作業時間（速報）を{member}・日ごとに出します。計画 = 今月のリソース計画の配分 × {standardHours}h、残り/日 = (計画 − 累計) ÷ 残りの営業日。計画を超えた人は「超過」です。
