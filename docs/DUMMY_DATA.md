# ダミーデータのシナリオ

`npx tsx scripts/generate-dummy.ts [--seed 42] [--asOf 2026-10-27] [--out data] [--base-only]` で生成する架空の会社のデータ。
同じ seed・asOf なら毎回バイト単位で同じ出力になる（乱数は mulberry32、`_meta.json` の日時も asOf から導出）。
デモと結合テスト・E2E はこのデータを前提にしている。会社名・人名はすべて架空。

2 つの部分でできている。

1. **基本シナリオ**（このページの前半）: 手で作った 6 チーム・30 人・21 契約。テストの期待値（C005 の端数、C008 の超過など）はここに置く。
2. **実運用規模の部分**（後半「実運用規模の部分」）: 4 事業部・約 130 人・約 80 契約を足し、全体を元の約 5 倍にする（`scripts/dummy-scale.ts`）。
   乱数列・メンバー・契約は基本シナリオと分けてあるので、基本シナリオの数値は変わらない（`--base-only` で基本シナリオだけを出すと旧データと同一）。

## 作業実績（`data/worklogs/YYYY-MM.csv`）

- 2025-04-01 〜 asOf（既定 2026-10-27）の**平日のみ**。土日と `holidays.csv` の日は無い。
- 1 人 1 日 6〜8h を 1〜3 件に 0.25h 刻みで分ける。課長は 2〜4h。4% の日は丸一日休み。
- 契約の選び方は所属チームの契約を月額に比例した重みで。**約 10% は他チームの契約への応援**（`memberTeamId` ≠ 契約のチーム）。
- 0.25 / 0.5 のような小さい時間が混ざる（C013、C009、分割の端数）。
- **hours = 0 の行**: `2026-05-12, M014, 株式会社ひまわり食品`（無視される。`WORKLOG_INVALID_HOURS`）。
- 作業内容は 定例 / 問い合わせ対応 / 障害対応 / 調査 / リリース作業 / 監視・運用 / パッチ適用 / ドキュメント更新 / 改修 / テスト。幽霊メンバーは「データ移行」、C010 準備は「導入準備」。
- **契約外の作業**（SPEC §30。本体とは別の乱数列で上乗せするので、契約の数値は変わらない）:
  - 青葉物流の更改提案（M010・M011、2026-06〜10、「提案」「見積」）→ 関連契約 C002。C002 の実績には入らない。
  - みなと銀行の運用設計（M015・M017、2026-08〜10、「運用設計」）→ 関連契約 C004。
  - 新規見込み「株式会社さくらんぼ交通 / 運行管理システム提案」（M019、2026-08〜10）→ 紐付けルールなし。契約外なので未紐付け警告は出ない。工数画面の顧客別で「契約外だけの顧客」として出る。
- 行は 日付 → メンバー → 顧客 → 案件 → 時間 → 作業内容 の順に並ぶ（生成と取得スクリプトで共通の並び）。
- `_meta.json`: `{ fetchedAt: "<asOf>T09:00:00+09:00", adapter: "dummy", seed, asOf }`。

## 作業種別の分類表（`data/task-types.csv`）

上の作業種別を「契約内」「契約外」に分ける（提案・運用設計・見積が契約外）。**「勉強会」はわざと載せていない**（未分類の警告 `TASK_UNCLASSIFIED` の例。契約内として数える）。「社内会議」は顧客名が空で分類より先に除外されるので載せていない。

## 別シナリオを作る

- `--seed` を変えると工数の乱数だけ変わる（マスタ・契約は固定）。
- `--asOf` を早めると作業実績の期間が短くなる（例 `--asOf 2025-12-15` で FY2025 途中の状態）。
- 基本シナリオのマスタや契約を変えたいときは `scripts/generate-dummy.ts` の `TEAMS` / `MEMBERS` / `RATES` / `CONTRACTS` / `MAPPINGS` を、実運用規模の部分は `scripts/dummy-scale.ts` を編集する。
