# 画面の文言を書き換える

画面に出る日本語（見出し・説明・ボタン名・警告・計算根拠パネル・Excel の列名など）は、プログラムとは別のファイルにまとめてあります。
文言だけを直すなら、プログラムを読む必要はありません。

| ファイル | 中身 |
|---|---|
| `src/i18n/ja.js` | ほぼすべての画面の文言（分類ごとにまとめてあります） |
| `src/i18n/rules.txt` | 「計算ルール」画面の本文（Markdown） |
| `src/i18n/guide.txt` | 「使い方」画面（利用者向けのマニュアル）の本文（Markdown） |

GitLab の画面でファイルを開いて「編集」から直し、コミットすれば CI がビルドし直して反映します（ローカルの準備は不要）。

## 1. ja.js の書き換え方

```js
  teams: {
    orgNote: "期間の終了月（{month}）時点の組織で集計しています。",
    empty: "チームがありません",
  },
```

- 書き換えるのは `"` と `"` の間だけです。左側の名前（`lead:` など）は変えないでください。プログラムはこの名前で文言を探します。
- 行末の `,` は消さないでください。
- 文中に `"` を書きたいときは `\"` と書くか、「」を使ってください。
- 探すときは、画面に出ている言葉でファイル内を検索するのが早道です。同じ言葉が複数あるときは、上の `// ──` の見出し（どの画面のものか）で見分けます。
- `common`（どの画面でも使う言葉）や `columns`（表の列名）を直すと、それを使う全画面が変わります。
- 各画面の `lead`（画面の説明）と `…Hint`（セクションの補足）は、画面上では見出し横の「?」にカーソルを合わせたときだけ出ます。
- 画面の本文（「?」の外）に出る文言は短くしてください。各画面の本文の文章は合計 120 文字・1 段落 70 文字までで、超えると `npm run test:e2e`（`tests/e2e/screen-text.spec.ts`）が落ちます。説明を足したいときは `…Hint` か `lead` に書きます。

### 差し込み口 `{name}`

`{件数}` のような値が入る場所は `{n}` `{month}` `{team}` のように波かっこで書いてあります。

- 中の英字は変えないでください。位置は自由に動かせます。使わないなら消してもかまいません。
- 綴りを間違えると、画面に `{mont}` のようにそのまま出ます（`npm test` でも検出します）。

### 太字などのタグ

一部の文言（マスタ編集画面の説明など）は `<strong>…</strong>` などの HTML タグをそのまま表示に使います。タグは開きと閉じを対にしてください。

## 2. rules.txt（計算ルール画面）の書き換え方

Markdown で自由に書き換えられます（見出しは `##`、表は `|` 区切り）。先頭の `<!-- … -->` の中は画面に出ません。

本文中の次の `{name}` は、`config.json` などの現在の値に置き換わります。これ以外の波かっこはそのまま表示されます。コードブロック（```` ``` ```` で囲んだ部分）の中では置き換わりません。

| 書き方 | 置き換わる値 |
|---|---|
| `{contract}` `{customer}` `{project}` `{team}` `{member}` | 呼び名（`config.json` の `labels`。既定は 契約・顧客・案件・チーム・メンバー） |
| `{costTypes}` | 実績の種類の一覧 |
| `{threshold}` | 消化率で赤にする閾値（例: 100%） |
| `{fy}` `{fyStartMonth}` `{fyEndYear}` `{fyEndMonth}` | 年度・年度の開始月・終了年・終了月 |
| `{asOf}` `{asOfMonth}` `{lastFinalMonth}` | 計算基準日・基準月・確定済みの最終月 |
| `{closingDay}` | 工数確定の営業日（翌月 N 営業日） |
| `{standardHours}` `{dayHours}` | 月の標準時間・1 日の時間 |
| `{recentMonths}` | 着地見込みで平均する直近の月数 |
| `{methodDefault}` `{methodRecent3}` `{methodAll}` `{methodAssignment}` | 着地見込みの方式名（既定・直近平均・全実績・アサイン） |

ページの見出しと冒頭の説明は `ja.js` の `app.pages.rules` と `rules.lead` です。

## 2-2. guide.txt（使い方画面）の書き換え方

書き方と差し込み口は rules.txt と同じです。加えて次の決まりがあります。

- 節の見出しは `## 番号. 名前` で書きます。画面の先頭の目次はこの見出しから自動で作られ、`[8. マスタ編集](#8)` のように番号で節へリンクできます（番号を付け替えたら本文の `#番号` も直してください。`npm test` が行き先の無いリンクを検出します）。
- 画面へのリンクは `[リソース計画](./plan)` のように `./` から書きます。
- 読むのは利用者（経営層〜メンバー）です。README・docs・リポジトリなど、利用者が見られない文書へ誘導しないでください（`npm test` が「README」「docs/」などの語を検出して落ちます。`ja.js` の文言も同じ検査の対象です）。

ページの見出しと冒頭の説明は `ja.js` の `app.pages.guide` と `guide.lead` です。

## 3. 書き換えたあとの確認

- GitLab で直した場合: CI（テスト）が通れば反映されます。失敗したら、直した行の `"` や `,` の消し忘れをまず確認してください。
- ローカルで確認する場合: `npm test` で、存在しない名前の参照・差し込み口の書き間違い・空の文言を検出します。
  `rules.txt`・`guide.txt` を直したあとに `npm run dev` で確認するときは、先に `npm run clean` を実行してください（計算ルール・使い方の画面はビルド結果を保存しているため、そのままだと古い本文が出ます）。

## 4. ここに無い文言

- ブラウザのタブに出るページ名は、各ページ（`src/*.md`）の先頭 `title:` にあります（計算ルール・使い方の画面だけは `ja.js` の `app.pages.rules`・`app.pages.guide`）。
- 入力データの読み取り時にだけ出る開発者向けのエラー（`RangeError` など）や、社名の正規化に使う語（`株式会社` など）はプログラム側に残しています。
- `aria-label="読み込み中"`（読み込み中の表示の読み上げ用）は各ページの先頭にあります。

## 5. 開発者向け

```js
import { T, fmt, rich } from "../i18n/index.js";
T.common.loading                         // 文言そのもの
fmt(T.teams.orgNote, { month: "…" })     // {name} を値に置き換えた文字列
rich(T.mastersPage.introMembers)         // タグを含む文言を要素にする（値はエスケープ）
```

新しい文言は画面に直接書かず、`ja.js` の該当する分類に名前を付けて追加してください。`tests/unit/texts.test.ts` が参照漏れと差し込み口の不足を検査します。
